ルーティングは React Router 不使用。`App.tsx` で `window.location.pathname` を正規表現判定。
- `/p/:slug` → 顧客向け提案ページ（認証不要で到達、PIN で閲覧）
- それ以外 → 管理画面（JWT ログイン）

## 2. データモデル（`backend/prisma/schema.prisma`）

- `Admin` — 管理者（PBKDF2 ハッシュ、role: staff/admin）
- `Customer` — 顧客。`accessCode`（4桁数字・unique）が提案閲覧 PIN。
- `Property` — 物件マスター。賃貸/売買の4種別。`stations/highlights/facilities/images` は Json。`rent`/`maintenanceFee` のみ数値、他の契約条件は文字列。`status: 公開/下書き`。
- `Proposal` — 顧客に紐づく提案。`slug`(8文字 base64url)・`title`・`message`・`status: 下書き/送信済み`。
- `ProposalItem` — 提案内の物件（order 付き）。

## 3. 顧客向け API（`backend/src/routes/publicProposals.ts`）

- `GET /api/p/:slug/meta` — 認証不要。顧客名・会社名を返す（PIN 画面の「○○様」表示用）。
- `GET /api/p/:slug` — `X-Access-Code` ヘッダ or `?code=` で認証。顧客の `accessCode` と一致すれば提案全体（items + property 全フィールド）を返す。
- 提案の `status`（下書き）や物件の `status`（下書き）は**チェックしていない**。

## 5. コードリーディングで見つけた課題（改善候補の元ネタ）

### A. バグ・不具合（優先度高）
1. **PIN 不一致のエラーが表示されない** — `CustomerAppAuth` が `useState(errorMessage)` で初期化しているため、親から後で渡される `authError` が反映されない。本番で間違った PIN を入れても無反応に見える。
2. **間取り図が2回表示される** — Detail で価格の下に1回、概要タブの FLOOR PLAN セクションでもう1回。
3. **ブラウザの「戻る」で離脱する** — stage 切替は history に積まれないため、詳細→戻るでサイトを離れる。list に戻ってもスクロール位置が先頭に戻る。
4. **♡（お気に入り）が保存されない** — ローカル state のみ。戻ると消える。顧客の反応も担当者に伝わらない。
5. `index.html` の `lang="en"` → `ja` が正しい（読み上げ・フォント選択に影響）。
6. PIN 送信中のローディング表示なし。二重送信可。

### B. UX・訴求（顧客体験）
7. CTA が「物件名をコピー」だけで、実際の問い合わせ導線（LINE / 電話 / メール / 担当者名）がない。富裕層向けには担当者直通の導線が有効。
8. カルーセルに「SWIPE →」と表示されるが、実際はスワイプ非対応（ボタンのみ）。
9. PC で開くと中央に細い1カラム。顧客が PC/タブレットで見る場合の見え方の検討余地。
10. 売買物件（売買マンション/戸建て）でも「¥xxx / 月」表記になる（`rent` しか数値項目がない）。
11. ページタイトル/OG が固定。提案ごとのタイトルが `document.title` に反映されない。
12. 再読み込みで PIN 再入力が必要（sessionStorage 等で保持する余地）。
13. 画像が Cloudinary 変換なし・lazy loading なしで配信（f_auto,q_auto,w_ 指定で軽量化可）。
14. アイコンボタン（♡ ‹ ›）に aria-label なし。

### C. セキュリティ・運用
15. 4桁 PIN に対するレート制限・ロックアウトなし（総当たり 1万回で突破可）。
16. `下書き` 状態の提案・物件も URL+PIN で閲覧できる。
17. `/meta` は認証なしで顧客名を返す（URL を知っていれば顧客名が分かる）。
18. 物件の住所（`address`）を全文表示している。未公開物件の扱いは要方針。
