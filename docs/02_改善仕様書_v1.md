## A. 初期表示の高速化

### A-1. 「読み込み中…」ゲートの撤廃（効果: 大・確実）
- 現象: `CustomerProposal.tsx` が `/meta` の応答を待ってから PIN 画面を出す。API が寝ていると数十秒白紙。
- 方針: **PIN 入力画面を即座に描画**し、顧客名（「○○様」）は `/meta` が返ってきたら差し込む（それまで「お客様」表示 or スケルトン）。`/meta` が 404 のときのみ「提案が見つかりません」に切替。
- 対象: `frontend/src/pages/customer/CustomerProposal.tsx`
- 受け入れ: API を止めた状態（またはネットワーク遅延シミュレート）でも PIN 画面が 1 秒以内に表示される。

### A-2. API のスリープ対策（効果: 大）— 決定: (b)+(c)
- (b) UptimeRobot（無料枠）で `https://tokyo-land-backend.onrender.com/api/health` を **5 分間隔** で HTTP 監視。Render Free の無料枠は月 750 インスタンス時間なので、1 サービス常時起動（約 744 時間）は枠内。ダウン通知メールも副次的に得られる。
- (c) フロント側: `/p/` ルート描画と同時に `/api/health` を先行フェッチ（ウォームアップ）。監視が止まっていた場合の保険。
- 対象: 外部サービス（平林さん作業）/ `CustomerProposal.tsx`
- 受け入れ: 15 分放置後にアクセスし、PIN 送信から一覧表示まで 3 秒以内。UptimeRobot の応答時間グラフが継続して 1 秒未満。
- 注意: Render の無料枠ポリシーは変更されることがある。月末に「Free instance hours」の消費を一度確認する。

### A-3. フォント読み込みの最適化（効果: 中）
- 方針:
  1. `index.css` の `@import` をやめ、`index.html` の `<head>` に `<link rel="preconnect" href="https://fonts.googleapis.com">` `<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>` ＋ `<link rel="stylesheet" ...>` を置く（CSS 内 @import のブロッキング連鎖を解消）。
  2. ウェイトを削減: Noto Serif JP 400/500、Noto Sans JP 400/500、JetBrains Mono 400 のみ（700 の使用箇所を grep し、500 に置換）。
  3. `display=swap` は維持（システムフォントで即描画→差し替え）。
- 対象: `frontend/index.html`, `frontend/src/index.css`, 700 使用箇所
- 受け入れ: `document.fonts.size` が 1/3 以下、初回描画（FCP）が改善。

### A-4. バンドル分割（効果: 小〜中）
- 方針: `App.tsx` で `AdminApp` を `React.lazy` + `Suspense` にし、顧客ルート `/p/` では管理画面コードを読み込まない。`index.html` の `lang="ja"` もここで修正。
- 対象: `frontend/src/App.tsx`, `frontend/index.html`
- 受け入れ: `/p/` 初回ロードの JS 合計が現状より 30% 以上減る（`npm run build` の出力で確認）。

## B. バグ・UX 修正

### B-1. PIN 不一致エラーが表示されない
- 原因: `CustomerAppAuth.tsx` の `useState(errorMessage ?? null)` は初期値のみ。親の `authError` 更新が反映されない。
- 方針: `errorMessage` の変化を `useEffect` で `error` に同期（または内部 state を廃止し、親エラー＋ローカル検証エラーの合成表示）。あわせて**送信中はボタン disabled + 「確認中…」**、失敗時は 4 マスをクリアして 1 マス目にフォーカス。
- 対象: `CustomerAppAuth.tsx`, `CustomerProposal.tsx`
- 受け入れ: 本番で誤 PIN → 赤字「アクセスコードが一致しません」が出る。管理画面プレビュー（`correctCode` 経路）でも従来通り動く。

### B-2. 間取り図の二重表示
- 方針: `CustomerAppDetail.tsx` の価格直下の間取り図ブロックを削除し、概要タブ内「FLOOR PLAN」セクションに一本化。→ **一本化先は「概要タブ内」**（価格→ハイライト→説明→アクセス→所在地→間取り→建物の流れが自然）。
- 受け入れ: 間取り図が 1 回だけ表示される。設備タブに切替えても消える。

### B-3. ブラウザ「戻る」で離脱／スクロール位置が戻らない
- 方針: stage 遷移を `history.pushState` に載せる。
  - list → detail: `pushState({stage:'detail', itemId}, '', `/p/${slug}#${itemId}`)`
  - `popstate` で state を読み stage を復元。detail から戻ると list。auth 画面では戻る=離脱で OK。
  - list のスクロール位置を ref に保持し、復帰時に `window.scrollTo` で復元。
- 対象: `CustomerProposal.tsx`（stage 管理を URL ハッシュと同期）
- 受け入れ: 詳細→ブラウザ戻る→一覧（同じスクロール位置）。詳細 URL（#付き）を再読込しても PIN 入力後にその物件詳細が開く。管理プレビュー（`ProposalPreview.tsx`）は history を触らない（prop で無効化）。

### B-6. カルーセルのスワイプ対応
- 方針: ボタン送りを維持しつつ、`touchstart/touchend`（または Pointer Events）で水平 50px 以上の移動を検知して前後移動。「SWIPE →」ラベルは画像 2 枚以上かつ初回のみ表示（現状維持）。
- 対象: `CustomerAppDetail.tsx`
- 受け入れ: iPhone Safari / Android Chrome で左右スワイプで画像が切り替わる。縦スクロールを阻害しない。

### B-9. 下書きの非表示
- 方針（バックエンド）: `publicProposals.ts`
  - 提案 `status === '下書き'` → `/:slug` も `/:slug/meta` も 404 相当（`code: 'NOT_FOUND'`、文言「この提案は現在公開されていません」）。
  - items は `property.status === '公開'` のみ返す（下書き物件を除外）。
  - 同コミットで `render.yaml` の `disk:` ブロックを削除（Free 非対応・Cloudinary 移行済み）。
- 対象: `backend/src/routes/publicProposals.ts`, `render.yaml`
- 受け入れ: 管理画面で提案を「下書き」に戻すと顧客 URL で見えなくなる。「送信済み」に戻すと見える。下書き物件は一覧から消え、件数表示も減る。
- 注意: 管理画面の `ProposalPreview` は管理 API 経由なので下書きでも引き続きプレビュー可能（変更不要）。
